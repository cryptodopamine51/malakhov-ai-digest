AWS представила Context — сервис графа знаний для ИИ-агентов

Подготовлено редакцией Malakhov AI

AWS Machine Learning Blog·17 июн.·2 минЛабораторииКод

На AWS Summit New York City компания анонсировала AWS Context — сервис, который автоматически строит граф знаний из существующих корпоративных данных и предоставляет агентный поиск для ИИ-агентов. Это позволит агентам получать доступ к проверенным бизнес-правилам и предметным знаниям в runtime.

Кратко

  • —AWS Context создает граф знаний, связывающий данные из разных хранилищ.
  • —Сервис базируется на технологии, которая уже обрабатывает миллионы запросов в день в Amazon Quick.
  • —Контекст публикуется в открытом формате Apache Iceberg в S3 для портируемости.
  • —Каждый запрос к графу проходит через IAM и Lake Formation, обеспечивая аудит.
  • —Также анонсирован предварительный просмотр бизнес-контекста и семантического поиска для AWS Glue Data Catalog.
Глоссарий · 5 терминов▾
Граф знаний
Структура данных, в которой сущности (например, таблицы, дашборды, бизнес-правила) связываются отношениями, позволяя агентам и пользователям находить релевантный контекст.
Агентный поиск
Механизм поиска, оптимизированный для ИИ-агентов: агент отправляет запрос и получает структурированный ответ с проверенными данными и связями.
Apache Iceberg
Открытый табличный формат для хранения больших наборов данных, обеспечивающий совместимость с различными аналитическими движками.
IAM
Сервис управления доступом в AWS, определяющий, какие действия разрешены пользователю или сервису.
Lake Formation
Сервис AWS для построения и управления data lake с гранулярным контролем доступа к данным.

На AWS Summit New York City компания представила AWS Context — сервис, который автоматически выявляет связи между корпоративными данными и строит из них граф знаний. Этот граф служит единым контекстным слоем для ИИ-агентов, позволяя им получать релевантную информацию в runtime, не требуя ручного поиска по разрозненным источникам.

По замыслу AWS, современные агенты ограничены тем контекстом, который они могут обработать. Данные разбросаны по data lakes, data warehouses, базам данных и потокам, а часть знаний хранится в головах сотрудников. AWS Context решает эту проблему, предоставляя агентам доступ к управляемым связям между данными, бизнес-правилам и предметным знаниям. За график отвечают стюарды данных — они через консоль просматривают выведенные связи, утверждают их и добавляют доменные описания.

Технология графа знаний, лежащая в основе AWS Context, уже используется в сервисе Amazon Quick, где ежедневно обрабатываются миллионы запросов. Теперь AWS расширяет эту технологию на всю организацию. Граф интегрируется с AWS Glue Data Catalog, Amazon SageMaker Unified Studio и AWS Lake Formation, что позволяет управлять доступом через существующие политики IAM и Lake Formation. Каждый вызов к графу наследует права вызывающего пользователя — таким образом обеспечивается аудит: можно точно определить, какие данные и под чьим полномочием запросил агент.

Ключевой особенностью является открытость. Все метаданные публикуются в формате Apache Iceberg в Amazon S3, поэтому их можно анализировать с помощью Amazon Athena, Amazon Redshift, Apache Spark или любого Iceberg-совместимого инструмента. Это делает контекст портируемым и не привязывает клиента к проприетарным API. Агенты обращаются к графу через API агентного поиска и инструменты MCP, независимо от того, запущены ли они на Amazon Bedrock AgentCore, Amazon EKS или на MCP-совместимых фреймворках.

Отдельно AWS объявила о предварительном запуске бизнес-контекста и семантического поиска для AWS Glue Data Catalog. Теперь можно обогащать таблицы, представления и колонки бизнес-описаниями, а затем искать их по смыслу. Эта функция работает поверх того же графа знаний и упрощает обнаружение данных как для людей, так и для агентов.
