ИИналитик v2: платформа бизнес-анализа по BABOK теперь работает с любыми LLM

Подготовлено редакцией Malakhov AI

Habr AI·18 июн.·3 минКод

Разработчик ИИналитика полностью переписал архитектуру платформы для бизнес-аналитиков: вместо 21 MCP-сервера, намертво привязанного к Claude Code, теперь используются CLI-скрипты, совместимые с любым харнесом и любой языковой моделью, включая локальные.

Кратко

  • —Архитектура переведена с MCP-серверов на CLI-скрипты: агент вызывает нужный инструмент по требованию, а не держит все 21 в контексте одновременно.
  • —Платформа поддерживает харнесы OpenCode, Kodik, Codex и Claude Code, а также локальные модели — для компаний с требованиями к изоляции данных.
  • —Kodik как российская альтернатива позволяет платить рублями без VPN и зарубежных карт, что снимает главную боль первой версии для российских пользователей.
  • —Новая «Доска навигации» позволяет подключиться к уже идущему проекту: платформа читает готовые артефакты и сама определяет текущую стадию по BABOK.
  • —В разработке — многоагентная система и дашборд для тимлидов, позволяющий отслеживать прогресс команды бизнес-аналитиков.
Глоссарий · 7 терминов▾
MCP-сервер
Model Context Protocol — стандарт подключения внешних инструментов к языковой модели; MCP-сервер — отдельный процесс, который предоставляет модели набор функций через этот протокол.
Харнес
Программная оболочка (agent harness), которая управляет языковой моделью: отправляет запросы, обрабатывает ответы, вызывает инструменты и ведёт диалог с пользователем.
CLI-скрипт
Программа, запускаемая из командной строки (Command Line Interface); в контексте ИИналитика — инструмент, который агент вызывает по требованию вместо постоянно загруженного MCP-сервера.
BABOK
Business Analysis Body of Knowledge — международный стандарт методологии бизнес-анализа, описывающий области знаний, задачи и техники работы бизнес-аналитика.
Контекстное окно
Максимальный объём текста, который языковая модель может удерживать в памяти одной сессии; переполнение контекста снижает качество ответов.
Локальная модель
LLM, развёрнутая на собственных серверах компании или на локальной машине — данные не передаются в сторонние облачные сервисы.
Трассировка требований
Процедура отслеживания связей между бизнес-требованиями, техническими решениями и тест-кейсами, позволяющая оценить последствия изменений.

Первая версия ИИналитика — платформы, которая ведёт бизнес-аналитика по проекту согласно методологии BABOK v3, — работала исключительно внутри Claude Code от Anthropic. Двадцать один MCP-сервер загружался в контекстное окно модели целиком и оставался там на всю сессию. Чем длиннее становился транскрипт, тем выше был риск галлюцинаций и ошибок — контекстное окно любой LLM конечно, и его переполнение деградирует качество ответов.

Чтобы обойти это, автор делил инструменты на пять наборов по областям знаний BABOK и переключал их вручную командой /restart. Технически это работало, но противоречило самой идее платформы: бизнес-аналитик не должен держать в голове техническую механику, он должен думать о проекте. Мелкая фрикция ломала концепцию.

ХарнесКлючевая роль в AIналитике v2Поддержка локальных моделей
OpenCodeОткрытый харнес, работает с любой модельюДа
KodikРоссийская разработка, оплата рублями без VPNДа
CodexКонсольный агент OpenAI для фанатов экосистемыНет
Claude CodeИсходный харнес первой версииНет

После публикации первой версии на Хабре пришла обратная связь, которая сложилась в три устойчивых сигнала. Первый — Claude в России труднодоступен: VPN, серые схемы оплаты, риск блокировки аккаунта. Второй — крупные компании не могут отправлять рабочие документы в сторонние облака: регламенты требуют, чтобы данные не покидали контур организации. Третий — страх переходить на новый инструмент в середине живого проекта: артефакты уже частично собраны, процесс идёт, и встроить в него незнакомую платформу психологически сложно.

В ответ на эти сигналы архитектура ИИналитика v2 была переписана полностью. Вместо MCP-серверов — CLI-скрипты: агент вызывает нужный скрипт ровно тогда, когда он требуется, получает результат и освобождает память. Фазы и команда /restart исчезли как класс. Скрипты не привязаны к конкретному харнесу, поэтому платформа теперь запускается под OpenCode, Kodik, Codex и Claude Code, а при необходимости архитектура позволяет подключить Cline, Roo Code, Aider и другие инструменты без болезненного рефакторинга.

Для российского рынка ключевым стал Kodik — отечественный харнес с оплатой в рублях, без VPN и иностранных карт, с поддержкой локальных моделей. OpenCode закрывает требования по безопасности: локальная LLM означает, что ни одна строка корпоративного документа не уходит на внешние серверы. Это принципиально для банков, госструктур и любых организаций с жёсткими политиками информационной безопасности.

Третий сигнал — страх переключения на середине проекта — решает новая «Доска навигации». Платформа читает уже существующие артефакты и самостоятельно вычисляет, на какой стадии по BABOK находится проект. Аналитику не нужно начинать с нуля или вручную объяснять системе контекст — она подхватывает проект там, где он есть.

С точки зрения бизнес-логики ИИналитик решает три задачи. Первая — выравнивание грейда: джуниор с платформой работает по методологии как мидл, потому что система не даёт пропустить шаг или отклониться от BABOK. Вторая — сохранение знаний: каждое действие аналитика фиксируется в структурированных артефактах, поэтому уход сотрудника не обнуляет контекст проекта, а онбординг нового аналитика сокращается с недель до часов. Третья — управление изменениями: при поступлении нового требования от стейкхолдера платформа за секунды показывает, какие существующие требования, тесты и решения оно затрагивает. Аргумент «по-быстрому не получится» перестаёт быть интуицией и становится конкретным списком зависимостей.

В разработке находятся многоагентная система и дашборд для тимлидов — инструмент, который даёт руководителю отдела сводную картину по всем проектам команды. Исходный код первой версии открыт на GitHub; вторая версия развивается в том же репозитории.
