Microsoft рассматривает DeepSeek V4 как дешёвую модель для Copilot Cowork

Подготовлено редакцией Malakhov AI

The Decoder·16 июн. 2026 г.·2 минИсследованияИндустрия

Microsoft изучает возможность подключить самостоятельно размещённую версию DeepSeek V4 к Copilot Cowork — и одновременно переводит сервис на тарификацию по фактическому потреблению. Решение ожидается в ближайшие недели, сообщает Axios.

Кратко

  • —Copilot Cowork работает на технологии Claude от Anthropic — агентная логика активно расходует токены, делая фиксированную подписку убыточной.
  • —EVP Copilot Чарльз Ламанна объяснил смену модели тем, что часть пользователей выполняет сотни задач в неделю.
  • —DeepSeek V4 будет опциональным и полностью размещённым на Azure — данные клиентов не покинут облако Microsoft.
  • —Модель доработана с защитными фильтрами; китайское происхождение DeepSeek может вызвать критику в США.
  • —GitHub Copilot уже перешёл на аналогичную схему оплаты — Cowork станет вторым продуктом Microsoft с такой моделью.
Глоссарий · 5 терминов▾
Агентная архитектура
Подход, при котором языковая модель самостоятельно планирует многошаговые задачи, вызывает внешние инструменты и корректирует результат без участия человека на каждом шаге.
Токен
Минимальная единица текста, которую обрабатывает языковая модель; стоимость работы модели обычно измеряется в количестве потреблённых токенов.
Usage-based billing
Модель оплаты по фактическому потреблению: клиент платит за реально использованные ресурсы, а не фиксированную сумму в месяц.
Fine-tuning (дообучение)
Дополнительное обучение уже готовой модели на специализированных данных, чтобы адаптировать её поведение под конкретные задачи или требования безопасности.
Self-hosted (самостоятельное размещение)
Запуск модели на собственной или арендованной инфраструктуре, при котором данные не передаются разработчику модели.

Copilot Cowork — корпоративный ИИ-инструмент Microsoft для совместной работы — строится на технологии Claude от Anthropic. Агентная архитектура Claude предполагает многошаговое рассуждение: модель самостоятельно планирует задачи, вызывает инструменты и итерирует результат. Это делает её мощной, но дорогой: каждый шаг рассуждения генерирует дополнительные токены, а значит, и затраты.

Именно здесь возникает экономическая проблема, которую Microsoft пытается решить. EVP направления Copilot Чарльз Ламанна объяснил Axios, что фиксированная подписка не работает, когда часть пользователей выполняет сотни задач в неделю: их потребление несопоставимо с медианным клиентом, и компания несёт убытки. Решение — перейти на тарификацию по фактическому потреблению, то есть платить за реально израсходованные токены или вычислительные ресурсы. Microsoft уже применила эту схему к GitHub Copilot; Cowork станет вторым крупным продуктом с такой моделью монетизации.

Параллельно компания рассматривает DeepSeek V4 в качестве более дешёвой альтернативы Claude для части задач. Речь идёт о самостоятельно размещённой и дополнительно дообученной версии модели — она будет работать исключительно на инфраструктуре Azure, без передачи данных клиентов за пределы облака Microsoft. Модель также прошла настройку с защитными фильтрами. Использование DeepSeek останется опциональным: пользователи смогут выбирать между моделями в зависимости от задачи и бюджета.

Китайское происхождение DeepSeek — потенциально чувствительный момент, особенно на американском рынке, где регуляторное давление на технологии из КНР остаётся высоким. Microsoft заранее подчёркивает изоляцию модели внутри Azure как ответ на возможную критику. Насколько этот аргумент убедит корпоративных клиентов и регуляторов — покажет реакция рынка после финального объявления, которое ожидается в ближайшие недели.

Логика происходящего вписывается в более широкую позицию CEO Сатьи Наделлы, изложенную в его публикации на этой неделе: будущее корпоративного ИИ — это экосистема моделей, которые компании выбирают и настраивают под конкретные задачи и бюджеты. Наделла ранее называл ИИ «бизнесом потребления» и говорил, что хочет видеть «интенсивных пользователей с интенсивным использованием». Переход на usage-based billing — прямое следствие этой философии: чем больше используешь, тем больше платишь, и Microsoft зарабатывает на росте потребления, а не на фиксированных подписках.
